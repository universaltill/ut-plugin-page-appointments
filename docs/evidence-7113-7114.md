## FINDING (blocks the #7114 acceptance): ut-docs#7280

The till builds the guest's module config without `WithRandSource`; wazero's
default is a **deterministic** source. Every fresh instantiation (one per
event) draws the same `crypto/rand` bytes, so the plugin's UUIDv4 ids repeat:
in the run, the first appointment got the id of the first resource. The next
booking then has the same id as the first, the engine's "ignore myself" rule
hides the real overlap, and the guarded INSERT collides on the primary key.
Result for an operator: a second booking is refused ("That time is no longer
free") or the guest exits, overlapping or not. Any plugin using `crypto/rand`
is affected (ids, nonces). Fix is one line in the host
(`internal/plugins/wasm_runtime.go`), carded as ut-docs#7280. The two
affected tests pass unchanged with that line applied locally.
